# ระบบเช็กการเข้าเรียน (เวอร์ชัน Vercel + Supabase)

ผู้เรียนเปิดหน้านี้ในหน้าต่างแยกคู่กับห้องเรียนออนไลน์ (Meet / Zoom / Teams) ระบบบังคับให้แชร์ทั้งหน้าจอ
บันทึกเวลาที่แชร์และเวลาที่หยุดแชร์ลงฐานข้อมูล และผู้สอนดูสถานะกับภาพหน้าจอย่อได้จากแดชบอร์ด

- หน้าเว็บ: โฮสต์บน Vercel (ไฟล์สถิตทั้งหมด ไม่ต้องมีเซิร์ฟเวอร์)
- ฐานข้อมูลและระบบล็อกอิน: Supabase (ไม่ได้ใช้ Realtime จึงไม่ติดโควตาการเชื่อมต่อพร้อมกัน)
- เวลาทุกอย่างอ้างอิงเวลาของเซิร์ฟเวอร์ฐานข้อมูล ผู้เรียนแก้เวลาเองไม่ได้

## ตั้งค่า (ทำครั้งเดียว ประมาณ 15 นาที)

### 1) สร้างโปรเจกต์ Supabase
1. สมัครที่ supabase.com แล้วกด New project (แผนฟรีใช้ได้)
2. ไปที่ Authentication > Sign In / Providers แล้วเปิด **Allow anonymous sign-ins** (ผู้เรียนไม่ต้องสมัครสมาชิก ระบบสร้างตัวตนชั่วคราวให้เอง)
3. ไปที่ Authentication > Users > Add user ใส่อีเมลและรหัสผ่านของผู้สอน (ติ๊ก Auto Confirm User)
4. เปิดไฟล์ `supabase/setup.sql` แก้บรรทัดท้ายไฟล์ `ใส่อีเมลผู้สอน@example.com` เป็นอีเมลผู้สอนข้อ 3 แล้วคัดลอกทั้งไฟล์ไปวางที่ SQL Editor แล้วกด Run (รันซ้ำได้ ไม่เสียหาย)
5. ไปที่ Project Settings > API คัดลอก **Project URL** และ **anon public key**

### 2) ใส่ค่าในหน้าเว็บ
เปิด `public/config.js` แล้วแทนที่ `SUPABASE_URL` และ `SUPABASE_ANON_KEY` ด้วยค่าจากข้อ 5
(anon key เป็นกุญแจสาธารณะ ใส่ในหน้าเว็บได้ ส่วน **service_role key ห้ามใส่เด็ดขาด**)

### 3) นำขึ้น Vercel
1. สร้าง repository ใน GitHub แล้วอัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้นไป (รวมโฟลเดอร์ `public`, `supabase`, ไฟล์ `vercel.json`)
2. ที่ vercel.com กด Add New > Project เลือก repository นั้น ไม่ต้องตั้งค่า Framework หรือ Build Command (ไฟล์ `vercel.json` กำหนด output เป็นโฟลเดอร์ `public` แล้ว) กด Deploy
3. ได้ลิงก์ เช่น `https://ชื่อโปรเจกต์.vercel.app`

## วิธีใช้งาน

1. ผู้สอนเปิด `/teacher` ล็อกอินด้วยอีเมลที่ตั้งไว้ ใส่ชื่อห้องที่ช่อง "สร้างห้องใหม่" (เช่น MATH101) แล้วกดสร้างห้อง
2. ส่งลิงก์ `/student` และรหัสห้องให้ผู้เรียน ผู้เรียนกรอกรหัสห้อง ชื่อ แล้วเลือกแชร์ "ทั้งหน้าจอ"
3. ผู้เรียนเปิดห้องเรียน Meet/Zoom/Teams ตามปกติ และเปิดหน้านี้ค้างไว้ในหน้าต่างแยกตลอดคาบ
4. ผู้สอนดูสถานะสดบนแดชบอร์ด (อัปเดตทุก 10 วินาที) กำหนดช่วงเวลาเรียนที่ช่อง "เริ่มนับตั้งแต่ / ถึง" และกด "ดาวน์โหลดรายงาน CSV" เมื่อจบคาบ

เกณฑ์ต่าง ๆ ปรับได้ที่ `public/config.js`: หยุดแชร์เกินกี่วินาทีถึงนับว่าผิดกติกา (GRACE_SECONDS) ความถี่ภาพย่อ (FRAME_SECONDS) และเวลาที่ไม่มีสัญญาณแล้วถือว่าหลุด (OFFLINE_AFTER_SECONDS)

## ความปลอดภัยของข้อมูล

- ผู้เรียนเขียนข้อมูลได้เฉพาะของตัวเอง อ่านข้อมูลของคนอื่นไม่ได้ ภาพหน้าจอและรายงานอ่านได้เฉพาะบัญชีที่อยู่ในตาราง `teachers`
- ผู้ที่ไม่ได้ล็อกอินเข้าถึงตารางไม่ได้เลย
- ผู้เรียนที่รู้เทคนิคยังปลอมสถานะจากฝั่งเบราว์เซอร์ได้ (เช่น ส่งสัญญาณว่ากำลังแชร์ทั้งที่ไม่ได้แชร์) ระบบไม่ใช่เครื่องมือคุมสอบ ควรใช้ร่วมกับการสุ่มถามหรือแบบทดสอบสั้น ๆ ระหว่างคาบ
- ภาพหน้าจอเป็นข้อมูลส่วนบุคคล ต้องแจ้งวัตถุประสงค์และขอความยินยอมตาม PDPA ก่อนใช้ สำหรับผู้เรียนที่เป็นเด็กต้องได้รับความยินยอมจากผู้ปกครอง
- ลบข้อมูลเก่าได้ที่ SQL Editor เช่น `delete from events where created_at < now() - interval '90 days';` และ `delete from thumbs where updated_at < now() - interval '1 day';`

## ข้อจำกัดและข้อควรระวัง

- ใช้ได้บนคอมพิวเตอร์ที่ใช้ Chrome หรือ Edge มือถือและแท็บเล็ตส่วนใหญ่แชร์หน้าจอผ่านเบราว์เซอร์ไม่ได้
- ภาพที่ผู้สอนเห็นเป็นภาพย่อที่รีเฟรชทุกประมาณ 15 วินาที ไม่ใช่วิดีโอสด
- ปริมาณข้อมูล: ผู้เรียน 100 คน ส่งภาพย่อทุก 15 วินาที ใช้ข้อมูลที่ผู้สอนดาวน์โหลดประมาณหลายร้อย MB ต่อคาบ 90 นาที (ประมาณการ ยังไม่ได้วัดกับของจริง) แผนฟรีของ Supabase มีโควตา egress รายเดือนจำกัด ถ้าใช้บ่อยให้เพิ่ม `FRAME_SECONDS` หรืออัปเกรดแพ็กเกจ
- การเข้าสู่ระบบแบบ Anonymous มีขีดจำกัดจำนวนครั้งต่อ IP ต่อชั่วโมง ถ้าผู้เรียนจำนวนมากใช้เครือข่ายเดียวกัน (เช่น ห้องคอมของโรงเรียน) อาจติดขีดจำกัด ปรับได้ใน Supabase Authentication > Rate Limits
- โปรเจกต์แผนฟรีของ Supabase อาจถูกพักการทำงานเมื่อไม่ได้ใช้งานนาน ให้เปิดแดชบอร์ดทดสอบก่อนคลาสจริงเสมอ (เงื่อนไขของ Supabase เปลี่ยนได้ ควรตรวจสอบหน้า Pricing)
